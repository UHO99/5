## 1. 실행 방법

### 요구사항
- Docker / Docker Compose

### 클론
```bash
git clone https://github.com/UHO99/HighFive.git
cd HighFive
```

### 백엔드 + MySQL + Redis + K6 이미지
```bash
cd backend
docker compose build k6 && docker compose up -d --build
```
대시보드의 "테스트 시작" 버튼은 백엔드가 호스트 도커 소켓으로 k6 컨테이너를 띄워서 동작하는데, `k6` 서비스는
`docker compose up`만으로는 안 만들어진다.
그래서 `build k6`를 먼저 실행해 이미지를 준비한 다음 나머지를 띄운다.

확인:
```bash
curl http://localhost:8080/1
```

기본 계정은 `ureca`/`ureca`입니다. 바꾸고 싶으면 실행 시 환경변수로 넘기면 됩니다:
```bash
DB_USER=myuser DB_PASSWORD=mypass docker compose up -d
```

종료:
```bash
docker compose down       # 컨테이너만 정지 (데이터 유지)
docker compose down -v    # DB 데이터까지 초기화
```

### K6 시나리오 추가
시나리오 목록은 `backend/k6/` 디렉터리를 스캔하는 게 아니라, 백엔드의 `K6Scenario` enum
(`global/common/enums/K6Scenario.java`)에 정의된 것만 대시보드에 뜨고 실행도 된다 - 클라이언트가 보낸
시나리오 id로 임의의 파일을 실행시키지 못하게 막는 화이트리스트다. 그래서 새 시나리오를 추가하려면:

1. `backend/k6/내스크립트.js` 작성. `BASE_URL`/`COUPON_ID`를 기존 스크립트들과 같은 방식으로 읽어야 한다:
   ```js
   const BASE_URL = __ENV.BASE_URL || 'http://localhost:8080';
   const COUPON_ID = __ENV.COUPON_ID || '1';
   ```
2. `K6Scenario` enum에 상수 추가 (`id, file, name, description, rampUp, hold, targetVus`) - 대시보드
   시나리오 다이얼로그에 그대로 노출되는 값들이다.
3. 백엔드 재빌드 + k6 이미지 재빌드 (둘 다 해야 목록/실행이 새 시나리오를 반영한다):
   ```bash
   docker compose build k6 && docker compose up -d --build
   ```
   enum엔 추가했는데 이미지 빌드를 깜빡하면, 실행 시 "아직 이미지에 반영되지 않았습니다" 에러로 바로
   알려준다.

## 2. 멘토링 질문 리스트

### 1. DB-Redis 정합성 확인 스케줄러, 실행 주기와 효율성은 어떻게 잡는지
```
DB와 Redis 상태를 주기적으로 대조하는 스케줄러를 만들 계획입니다. 실행 주기를 어떻게 잡는지, 데이터가 수백만 건으로 늘어나도 매번 전체를 안 훑고 효율적으로 확인하는 방법이 있는지 궁금합니다.
```

### 2. 성능 위해 JDBC 병행할지, 통일감 위해 JPA만 쓸 지
```
JPA의 `saveAll()`이 대량 데이터를 한 번에 flush 못하는 문제 때문에 JDBC Batch Insert를 사용하는데 팀 컨벤션 통일을 위해 JPA로 맞출지, 성능을 위해 JDBC를 사용할지 고민입니다.
```

### 3. 인프라 접근 코드는 도메인 패키지와 global 패키지 중 어디에 두는지
```
Redis처럼 특정 인프라에 종속된 코드를 그 인프라를 쓰는 도메인 패키지에 둘지, 전역(global/common) 패키지에 둘지 고민입니다. 프로젝트가 커질수록 어떤 기준으로 재배치를 판단하는지 궁금합니다.
```

### 4. Redis 실행 환경을 로컬과 Docker 중 무엇으로 할 지
```
개발 단계에서 Redis를 로컬에 직접 설치할지 Docker 컨테이너로 띄울지 고민했습니다. 실무에서는 이런 인프라를 어떤 기준으로 선택하는지, 팀원 간 환경 차이로 인한 문제는 어떻게 예방하는지 궁금합니다.
```

### 5. 배포 환경의 처리량-비용을 함께 고려한 용량 산정은 어떻게 하는지
```
로컬 환경에서 대규모 동시 요청을 시뮬레이션하고 있는데, 실제 서비스라면 "이 정도 트래픽에 어떤 사양/구성이 필요하고 비용이 얼마인지"를 설계 초기부터 같이 고려하는지, 일단 만들고 나중에 비용 최적화를 따로 하는지 궁금합니다.
```

### 6. 재고 대비 과도한 요청, "잘 처리했다"의 실무 기준은 무엇인지
```
재고 1만 건에 요청 2만 건이 몰리는 저희 시나리오처럼, 실무에서는 이런 상황의 처리 결과를 어떤 지표(응답 시간, 초과 발급 0건, 에러율)로 평가하는지, "이 정도면 합격"이라는 기준선을 어떻게 잡는지 궁금합니다.
```

### 7. 테스트용 더미 데이터를 실무에서는 어떻게 만드는지
```
회원 100만 명, 쿠폰 발급 이력 300만 건을 코드로 만들고 있습니다.
이때 쿠폰 상태 비율(발급 40% / 사용 40% / 취소 10% / 만료 10%)을 임의로 정했는데,
실무에서는 이런 비율을 어떤 근거로 정하는지, 그리고 비율이 달라지면 성능 측정 결과도 달라지는지 궁금합니다.
```

### 8. 트래픽이 몰리는 시간 범위를 어떻게 정하는지
```
재고 1만 장에 2만 명이 몰리는 시나리오인데, 동시라는 게 몇 초 안에 들어오는 건지가 정해져 있지 않습니다.
1초 안에 2만 건이 들어오는 것과 10초에 걸쳐 들어오는 건 완전히 다른 테스트라 생각해서, 실제 이벤트 오픈 때 트래픽이 어떤 모양으로 들어오는지, 보통 몇 초에 몰리는지 궁금합니다.
```

### 9. 스케줄러가 전부 스레드 하나를 공유하고 있는데, 이게 프로덕션에서 안전한가
```
Team5Application에 @EnableScheduling만 있고 별도 TaskScheduler 빈이 없습니다. 
Spring 기본값은 스레드 풀 크기 1개라서, 전부 같은 스레드를 나눠 씁니다. 
오래 걸리면 그 사이 컨슈머 틱이 밀리는 구조인데, 이런 걸 실무에서는 배치별로 풀을 분리하는지, 
아니면 처음엔 이렇게 시작해도 되는지 궁금합니다.
```
