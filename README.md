# 멘토링 질문 리스트

## 1. Redis → DB 비동기 반영에서 지연 허용 범위는 어느 정도인지
Redis에 먼저 요청을 적재하고 스케줄러가 주기적으로 읽어 DB에 반영하는 구조를 계획 중입니다. 이 시차를 실무에서는 보통 어느 정도까지 허용하는지, 사용자 응답에 영향이 안 가도록 어떻게 설계하는지 궁금합니다.

## 2. Batch Insert 크기는 뭘 기준으로 정하는지
batch size를 실무에서는 어떤 기준(DB 커넥션 풀, 트랜잭션 타임아웃, 메모리)으로 정하는지, 트래픽 상황에 따라 크기를 동적으로 바꾸기도 하는지 궁금합니다.

## 3. Redis가 갑자기 죽었을 때 데이터 유실은 어떻게 대비하는지
Redis는 메모리 기반이라 프로세스가 죽으면 아직 DB에 반영 안 된 데이터가 유실될 수 있습니다. AOF/RDB 같은 영속화 옵션을 실무에서는 얼마나 적극적으로 쓰는지, 아니면 유실을 감수하고 사후 검증으로 보완하는 쪽을 더 선호하는지 궁금합니다.

## 4. DB-Redis 정합성 확인 스케줄러, 실행 주기와 효율성은 어떻게 잡는지
DB와 Redis 상태를 주기적으로 대조하는 스케줄러를 만들 계획입니다. 실행 주기를 어떻게 잡는지, 데이터가 수백만 건으로 늘어나도 매번 전체를 안 훑고 효율적으로 확인하는 방법이 있는지 궁금합니다.

## 5. 성능 위해 JDBC 병행할지, 통일감 위해 JPA만 쓸 지
JPA의 `saveAll()`이 대량 데이터를 한 번에 flush 못하는 문제 때문에 JDBC Batch Insert를 사용하는데 팀 컨벤션 통일을 위해 JPA로 맞출지, 성능을 위해 JDBC를 사용할지 고민입니다.

## 6. 인프라 접근 코드는 도메인 패키지와 global 패키지 중 어디에 두는지
Redis처럼 특정 인프라에 종속된 코드를 그 인프라를 쓰는 도메인 패키지에 둘지, 전역(global/common) 패키지에 둘지 고민입니다. 프로젝트가 커질수록 어떤 기준으로 재배치를 판단하는지 궁금합니다.

## 7. Redis 실행 환경을 로컬과 Docker 중 무엇으로 할 지
개발 단계에서 Redis를 로컬에 직접 설치할지 Docker 컨테이너로 띄울지 고민했습니다. 실무에서는 이런 인프라를 어떤 기준으로 선택하는지, 팀원 간 환경 차이로 인한 문제는 어떻게 예방하는지 궁금합니다.

## 8. 배포 환경의 처리량-비용을 함께 고려한 용량 산정은 어떻게 하는지
로컬 환경에서 대규모 동시 요청을 시뮬레이션하고 있는데, 실제 서비스라면 "이 정도 트래픽에 어떤 사양/구성이 필요하고 비용이 얼마인지"를 설계 초기부터 같이 고려하는지, 일단 만들고 나중에 비용 최적화를 따로 하는지 궁금합니다.

## 9. 재고 대비 과도한 요청, "잘 처리했다"의 실무 기준은 무엇인지
재고 1만 건에 요청 2만 건이 몰리는 저희 시나리오처럼, 실무에서는 이런 상황의 처리 결과를 어떤 지표(응답 시간, 초과 발급 0건, 에러율)로 평가하는지, "이 정도면 합격"이라는 기준선을 어떻게 잡는지 궁금합니다.
